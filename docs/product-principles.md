# Product principles

1. **Data over perception.** Use execution data as the basis for delivery analysis.
2. **Immutable sprint baseline.** Preserve the original sprint baseline so later scope changes remain visible.
3. **Context explains metrics.** Interpret metrics alongside the context of delivery.
4. **Team-level analysis, not individual productivity ranking.** Analyze delivery at the team level.
5. **Auditability.** Keep analysis traceable to its source data and documented interpretation.
6. **A handoff to QA does not mean a User Story is complete.** QA handoff is an intermediate step.
7. **A User Story is fully completed only when it reaches Closed.** Closed is the completion boundary.

These principles guide the implemented Sprint Intelligence slices and future work.
